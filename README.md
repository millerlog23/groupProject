# ToTrak
*Group 8*

Application for tracking to-do tasks and assignments, with special functionality for assignments.

---

## Week 1
We are creating an application to track assignments and things to do as an extension beyond what we have done with coursework up until this point. Time permitting, there are options to extend features to allow notifications, gps tracking, or other more advanced add-ons.


### Domain Entity
Being an extension of the coursework, we will be utilizing multiple accounts to distinguish our work from what was already done. As such, we will be storing user ids, usernames, and passwords as well as developing a login flow. Outside of essential user information required for security, we have decided to store information locally and on the server.

Information here is considered a guide to how we will be designing the data's relationship. When appropriate, specfic types will be used in place of the data types stated here. During next week's work, we will experiment to determine what is the best method for storing this information. 

#### Courses
| Field | Type | Notes |
| --- | --- | --- |
| User ID | Integer | *From User Data* |
| Course ID | Integer | *Generated by Client* |
| Course Name | String | |
| Course Description | String | *Optional* |
| Last Updated | DateTime | *Generated by Client* |

Course ID is generated based on the largest Course ID present in the database for that user, thus User ID and Course ID are a combined primary key. Version is used to track who has the latest data.

#### Assignments
| Field | Type | Notes |
| --- | --- | --- |
| User ID | Integer | *From User Data* |
| Course ID | Integer | *From Courses* |
| Assignment ID | Integer | *Generated by Client* |
| Assignment Title | String | |
| Assignment Type | String | |
| Assignment Description | String | *Optional* |
| Due Date | DateTime | |
| Estimated Time | Integer | *Optional, represents minutes spent* |
| Completed | Boolean | |
| Last Updated | DateTime | *Generated by Client* |

Assignment ID is generated based based on the largest Assignment ID present in the database. User ID and Assignment ID are the combined primary key.

#### Task List
| Field | Type | Notes |
| --- | --- | --- |
| User ID | Integer | *From User Data* |
| Task ID | Integer | *Generated by Client* |
| Task Name | String | |
| Task Location | Integer | *From Task Locations, 0 is Unset* |
| Task Time | DateTime | |
| Task Type | String | |
| Completed | Boolean | |
| Last Updated | DateTime | *Generated by Client* |

Task ID is generated based on the largest Task ID present in the database. User ID and Task ID are the combined primary key.

#### Task Locations
| Field | Type | Notes |
| --- | --- | --- |
| User ID | Integer | *From User Data*|
| Location ID | Integer | *Generated by Client* |
| Location Name | String | |
| Last Updated | DateTime | *Generated by Client* |

We are seperating locations from the task list as we intend to let users sort by location as well as design their own intended ones. On account creation, three locations will be created for the user:
- Home
- School
- Work

These locations can be removed at any time, but also can have their name changed. When updating a task, users will have the ability to alter the location.

#### Audit
| Field | Type | Notes |
| --- | --- | --- |
| Change ID | Integer | *Generated by Server* |
| Change Time | DateTime | *Generated by Server* |
| User ID | Integer | *From User Data* |
| Entity Changed | String | |
| Change Type | String | |
| Affected ID | Integer | *Validated by Server* |
| Old Value | String | *May be Null if Create/Delete* |
| New Value | String | *May be Null if Create/Delete* |

The Audit table will be managed by the server rather than the client.
